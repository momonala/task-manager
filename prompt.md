# Cursor Project Setup Prompt

Create a Flask-based task management application with the following specifications:

## Project Structure
- Flask backend with SQLite database
- Single-page application with one main template
- Use Flask-SQLAlchemy for ORM
- Use Alembic for database migrations

## Database Schema

### Tickets Table
```python
- id: Integer, primary key
- title: String(200), NOT NULL
- description: Text, nullable
- project_id: Integer, foreign key to projects.id, NOT NULL
- status: String(50), NOT NULL, default='todo' (values: 'todo', 'in_progress', 'done', 'wont_do')
- acceptance_criteria: Text, nullable
- scope: Text, nullable  # JSON or text field for files affected, tests needed, risks, trade-offs, libraries
- prompt: Text, nullable  # markdown-formatted prompt for Cursor
- created_at: DateTime, NOT NULL, auto-generated
- updated_at: DateTime, NOT NULL, auto-updated on modification
```

### Projects Table
```python
- id: Integer, primary key
- name: String(100), NOT NULL, unique
- description: Text, NOT NULL
- localpath: String(500), NOT NULL
- last_modified: DateTime, auto-updated when any ticket in this project is marked as done
```

## UI Requirements

### Main Board View
- Dark mode theme inspired by Apple documentation aesthetics
- Three-column Kanban board layout: "To Do", "In Progress", "Done"
- Drag-and-drop functionality between columns using a lightweight library (e.g., SortableJS or dragula)
- Tickets display as cards showing: title, project name, created date
- Clicking a ticket opens a modal/panel for editing all fields
- "Won't Do" tickets are visually distinct (grayed out, moved to bottom or separate section)

### Ticket Actions
- Create new ticket (opens modal with required fields: title, project)
- Edit ticket (modal with all fields, clearly labeled which are optional)
- Delete ticket
- Mark as "Won't Do" (separate action from status changes)
- All optional fields (description, acceptance_criteria, scope, prompt) should have placeholder text: "Will be generated by AI" or similar

### Project Management
- Separate page or modal for creating/editing projects
- All four fields required when creating project
- List view of all projects with edit/delete actions

### Filtering & Display Options
- Toggle visibility of each column (To Do, In Progress, Done, Won't Do)
- Show/hide projects: "All", "None", or individual project selection (checkboxes)
- Date filter: "Show tickets from last X days" (dropdown or input, default: all time)
- Settings persist in localStorage or user session

### Settings Page
- Configure default values for filters
- Toggle options for board display
- Theme preferences (even though we start with dark mode)

## Technical Requirements
- Use Jinja2 templates
- CSS framework: Tailwind CSS (via CDN is fine for MVP)
- JavaScript: Vanilla JS or minimal Alpine.js for interactivity
- Database: SQLite (development), structure should allow easy PostgreSQL migration later
- No authentication/users for MVP (single-user app)

## Acceptance Criteria for MVP
1. I can create, edit, and delete projects
2. I can create tickets with title and project (required fields)
3. I can drag tickets between To Do, In Progress, Done columns
4. I can mark tickets as "Won't Do"
5. I can edit all ticket fields (even though some are empty initially)
6. I can filter by project and date range
7. I can hide/show columns
8. UI is dark mode and visually clean
9. Database migrations are set up properly with Alembic
10. All auto-generated timestamps work correctly

## Implementation Notes
- Keep the code simple and modular to easily add AI generation features next
- The `prompt` field should render in a `<textarea>` with monospace font
- The `scope` field can be a JSON text field or large textarea (we'll structure it better with AI later)
- Leave clear TODO comments where AI features will be added: "# TODO: Add AI generation button here"
- Use semantic HTML and ARIA labels for accessibility
